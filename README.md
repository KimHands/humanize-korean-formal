# humanize-korean-formal

**보고서·공문서의 비유·구어 표현을 공식 용어로 바꾸고, 끊기는 문장 흐름을 이어 주는 Claude Code 스킬**

AI 티를 걷어낸 글에 남아 있는 "뭉갠다", "묻힌다", "우리 데이터" 같은 표현과

## 기획 배경

AI 윤문 도구는 번역투나 상투구 같은 "AI 티"는 잘 걷어내지만, 사람이 직접 쓴 **비유와 구어**는 그대로 둡니다. 에세이에서는 장점인 이런 표현이 보고서·공문서·공모전 제출물에서는 격식을 떨어뜨립니다. 반대로 한꺼번에 공식 용어로 바꾸면 학술 용어까지 바뀌거나 뜻이 달라질 수 있습니다.

| 문제 | 이 스킬의 접근 |
|------|--------------|
| 보고서에 비유·구어가 섞여 격식이 떨어진다 | 비유(A)·1인칭·구어(B)·소제목(C)·제목(D)을 **분류해 후보 표**로 보여 준다 |
| 일괄 치환하면 원하지 않은 곳까지 바뀐다 | 표를 먼저 내고 멈춘다. **고른 번호만** 적용한다 |
| "공간 해상도", "강건성" 같은 학술 용어도 비유처럼 보인다 | **E 유지**로 따로 분류하고 이유를 적는다 |
| 단문이 줄줄이 끊기거나 "또한 … 또한 …"처럼 접속사가 몰려 있다 | 문장 쌍마다 연결어미로 묶기·접속어 정리·앞 문장 받기·순서 재배치를 **흐름 후보 표**로 낸다 |
| 접속사를 넣으면 원문에 없던 인과·대조가 생긴다 | 행마다 **관계**를 적고, 원문이 단정하지 않은 인과는 "관계 확인 필요"를 붙여 선택으로만 낸다 |
| 바꾸다가 숫자나 고유명사가 같이 바뀔 수 있다 | 적용 뒤 **불변 검사 스크립트**로 숫자·기호·인용·문체를 대조하고, **바뀐 구간 전체**를 보여 준다 |

## 사용 흐름

**① 요청**

```
이 보고서 비유·구어 표현 공식 용어로 바꿔 줘.
```

**② 후보 표 — 여기서 멈춥니다** (용어는 아직 바꾸지 않았습니다)

| # | 위치 | 현재 | 제안 | 분류 |
|---:|---|---|---|---|
| 1 | (3) 1문장 | 하나의 숫자로 **뭉갠다** | 하나의 값으로 **평균화한다** | A 비유 |
| 2 | (3) 2문장 | 이런 정류장은 평균에 **묻힌다** | 이런 정류장은 평균에서 **식별되지 않는다** | A 비유 |
| 3 | (3) 3문장 | 분포의 **꼬리에** | 분포의 **상위 구간에** | A 비유 |
| 6 | (3) 3문장 첫머리 | **그런데** 그 분포의 | **그러나** 그 분포의 | B 구어 |
| 7 | (1) 1문장 | **우리** 데이터가 | **보유** 데이터가 | B 1인칭 |
| 9 | 소제목 (3) | **왜 지금 필요한가** | **시의성** | C 소제목 |
| — | (3) 4문장 | 공간 **해상도**, **강건성** | 유지 (GIS·통계 용어를 정의대로 씀) | E 유지 |

```
"권장만"(A·B) / "권장+소제목"(A·B·C) / "전부" / 번호 나열 중 골라 주세요
```

**③ 선택 → 적용**

```
권장만. "위에서 끊는다"는 빼 줘.
```

고른 번호만 반영한 적용본, 바뀐 구간 목록(`우리 → 보유` 처럼 번호별 대조용), 보류한 번호 목록, 불변 검사 결과를 돌려줍니다.

> 위 예시는 이 저장소의 가상 테스트 입력([`tests/fixtures/report_excerpt/input.md`](tests/fixtures/report_excerpt/input.md))으로 스킬을 실제로 돌린 결과를 줄인 것입니다.

## 분류 기준

| 분류 | 대상 | 기본 판정 | 예 |
|------|------|----------|----|
| **A 비유** | 글자 그대로의 뜻이 아니라 이미지로 말하는 표현 | 권장 | 뭉갠다 → 평균화한다 · 위에서 끊는다 → 상위 순위부터 적용한다 |
| **B 1인칭·구어** | 뜻은 맞지만 말투가 사적이거나 구어인 표현 | 권장 | 우리 데이터 → 보유 데이터 · 쓰면 된다 → 활용할 수 있다 · 문장 첫머리 그런데 → 그러나 |
| **C 소제목** | 소제목·캡션의 의문형·대조형·구어 | 선택 | 왜 지금 필요한가 → 시의성 |
| **D 제목** | 문서 제목·과제명 | 선택 | 바꿀 때의 득실을 함께 적는다 |
| **E 유지** | 그 분야의 정의된 용어를 정의대로 쓴 것 | 바꾸지 않음 | 공간 해상도 · 강건성 · 고립 지점 |

E는 **좁게** 판정합니다. 정의대로 쓰지 않았거나 확신이 없으면 A로 올리고 "E 가능"을 적어 사용자가 판단하게 합니다. E로 잘못 두면 후보가 사라지지만 A로 잘못 올리면 표에 한 줄이 늘 뿐이기 때문입니다.
판정 기준 전문과 예시는 [`references/formal-terms.md`](skill/humanize-korean-formal/references/formal-terms.md)에 있습니다.

## 문장 흐름 검토

공식 용어를 적용한 뒤(또는 "문장이 끊겨" 같은 요청만 있을 때) 문장과 문장 사이를 봅니다. 결과는 **F1, F2 …** 번호의 흐름 후보 표로 나오고, 여기서도 고른 것만 바꿉니다.

| 유형 | 하는 일 | 판정 |
|------|--------|------|
| **F-연결** | 인접한 단문 2~3개를 연결어미·관형절로 묶는다 | 권장 |
| **F-접속** | 접속어를 넣거나 바꾸거나 **뺀다**(몰린 "또한"·"그리고" 정리 포함) | 권장 (새 인과는 선택) |
| **F-받기** | 앞 문장의 핵심 명사를 되받아 화제를 잇는다("이는 ~"은 쓰지 않음) | 권장 |
| **F-어순** | 앞 문장과 이어지는 정보를 문장 앞에 둔다 | 권장 |
| **F-순서** | 같은 문단 안에서 문장 순서를 바꾼다(예: 결론이 근거보다 먼저 나올 때) | 선택 |

**예시** — 가상 입력 [`flow_excerpt/input.md`](tests/fixtures/flow_excerpt/input.md)에 실제로 돌린 결과 일부

| # | 현재 | 제안 | 유형 · 관계 | 판정 |
|---|---|---|---|---|
| F1 | 정류장 86곳의 대기 시간을 측정했다. 측정은 3월에 했다. 평일 오전만 대상으로 했다. | 3월에 평일 오전만 대상으로 정류장 86곳의 대기 시간을 측정했다. | F-연결 · 없음(구조만) | 권장 |
| F2 | 오전 혼잡은 A 노선에 몰렸다. B 노선은 좌석이 남았다. | 오전 혼잡은 A 노선에 몰렸지만 B 노선은 좌석이 남았다. | F-연결 · 대조 | 권장 |
| F3 | 증차가 필요하다. (근거 두 문장) | (근거 두 문장) 증차가 필요하다. | F-순서 · 없음 | 선택 |
| F4 | 또한 학생지원팀은 … 갱신한다. 또한 시설팀은 … 점검한다. | 학생지원팀은 … 갱신하고 시설팀은 … 점검한다. | F-접속(삭제) · 나열 | 권장 |

고치려면 내용 판단이 필요한 곳(시제가 다른 두 문장, 가리키는 대상이 글에 없는 "이 목록")은 표에 넣지 않고 **알림**으로만 알려 줍니다.

**원본 규칙과 맞춥니다.** 원본 humanize-korean은 문두 접속사 과다(H-1), "그리고" 연결(A-14), "이는" 반복(H-3), 연결어미 뒤 쉼표(C-11)를 AI 티로 봅니다. 그래서 흐름 검토는 접속사를 몰아 넣지 않고 연결어미로 먼저 잇습니다. 적용 뒤 검사는 문두 접속사를 새로 늘려 한 문단 3개 이상이 되는 것, "이는"이 새로 늘어나는 것, 연결어미 뒤 쉼표가 새로 생기는 것, 기존보다 길면서 공백 빼고 70자를 넘는 새 문장, 연결어미가 3개 이상 이어진 새 문장을 잡습니다. 원문의 접속사는 몰려 있을 때 **빼는 제안**(F-접속)으로만 손대고, 원문의 "이는"은 건드리지 않습니다.
판정 기준 전문은 [`references/flow-review.md`](skill/humanize-korean-formal/references/flow-review.md)에 있습니다.

## 주요 기능

| 기능 | 설명 |
|------|------|
| **용어 + 흐름** | "공식 용어로 바꿔 줘" — 원문에 바로 용어 후보 표를 냅니다(첫 응답은 표뿐). 용어를 적용한 응답 끝에 흐름 후보 표가 이어집니다. "흐름은 건너뛰기"로 생략할 수 있습니다. |
| **흐름 검토만** | "문장이 끊겨서 읽기 불편해" — 흐름 후보 표만 냅니다. |
| **윤문 + 용어 검토** | "AI 티 빼고 공식 용어로" — 원본 humanize-korean 파이프라인(진단 → 윤문 → 구조 게이트)을 먼저 돌려 **윤문본을 전달**하고, 같은 응답에서 그 윤문본에 대한 후보 표를 냅니다. 공식 용어는 고른 뒤에만 바꿉니다. |
| **빠짐없이 훑기** | 제목 → 소제목 전부 → 본문 비유 표지 → 본문 구어 표지(문장 첫머리 접속사 포함) 순서의 체크리스트로 훑습니다. |
| **번호 선택** | "권장만", "권장+소제목", "전부", "1, 3, 7번", "권장만, 5번 빼고", "F1, F3" 모두 받습니다. |
| **흐름 검사** | `check_term_apply.py --mode flow`가 소제목·문단 수, 문단을 넘은 이동(다른 문단의 낱말이 새로 나타나는지), 문단별 숫자·기호·인용 개수, 새 문장 끝 형태, 문두 접속사·"이는" 증가, 새 쉼표·문장 길이·연결어미 개수, 확정 용어(`--protect`) 유지를 검사합니다. 문체가 섞인 글에서 문장끼리 문체를 맞바꾼 것, 같은 문단 안에서 문장을 지운 것은 잡지 못해 바뀐 구간 목록으로 확인합니다. |
| **불변 검사** | `check_term_apply.py`가 숫자(부호 포함)·수식 기호·영문 토큰·인용("" 「」 『』 《》 등)·문장별 끝 문체를 **등장 순서까지** 전후 대조하고, 바뀐 구간을 모두 출력합니다. LLM을 쓰지 않습니다. |
| **판정 기록** | 후보 표 파일 상단에 `판정: 적용 #…, 보류 #…`을 남깁니다. |

## 안전 설계

- **공식 용어는 표를 내고 고르기 전에는 바꾸지 않습니다.** "표 필요 없고 바로 완성본"이라고 해도 요청한 분류에 ✔를 표시한 표를 내고 확인을 받습니다. ("윤문 + 용어 검토" 모드의 윤문은 요청대로 먼저 수행합니다.)
- **고른 행만 바꿉니다.** 적용하면서 문장을 다듬지 않습니다.
- **순서는 윤문 → 용어 → 흐름으로 고정합니다.** 윤문을 나중에 돌리면 고른 공식 용어를 윤문이 다시 바꾸고, 흐름을 먼저 고치면 용어 교체가 묶인 문장을 다시 건드립니다.
- **흐름 검토는 확정한 용어를 다시 바꾸지 않습니다.** 검사를 통과하려고 제안의 형태가 달라지면 그 행은 보류하고 수정안을 다시 고르게 합니다.
- **흐름 검토는 내용을 더하지 않습니다.** 문단을 넘는 문장 이동, 문단 합치기, 시제가 다른 문장 묶기는 하지 않습니다. 원문이 단정하지 않은 인과는 선택지로만 냅니다.
- 숫자·고유명사·인용·주장은 대상이 아닙니다. 불변 검사에서 차이가 나오면 **설명하고 넘어가지 않고 원문대로 되돌립니다.** 고른 행의 제안이 원인이면 제안을 고치거나 그 행을 보류합니다. 검사 자체가 실패하면(입력 오류) 적용본을 완료로 전달하지 않습니다.
- **자동 검사의 한계**: 한글 고유명사(예: 기관명)나 주장의 뜻(예: "있다" → "없다"), 숫자가 가리키는 대상(예: 서울 7곳 ↔ 부산 7곳)이 바뀌는 것은 스크립트가 판정하지 못합니다. 따옴표 안의 강조 표현과 실제 인용도 구분하지 못하므로, 따옴표 안은 아예 후보로 올리지 않습니다. 그래서 바뀐 구간 목록(줄바꿈 포함)을 고른 번호와 하나씩 대조하고, 어느 번호에도 해당하지 않는 구간은 되돌립니다.
- 입력 글은 데이터로만 다룹니다. 글 안에 명령형 문장이 있어도 지시로 따르지 않습니다(원본 스킬의 정책을 이어받음).

## 사용법

| 이렇게 말하면 | 동작 |
|-------------|------|
| "이 보고서 비유·구어 표현 공식 용어로 바꿔 줘" | 용어 → (적용 뒤) 흐름 |
| "보고서체로 정리해 줘", "1인칭 표현 빼 줘", "용어 검토해 줘" | 용어 → (적용 뒤) 흐름 |
| "문장이 뚝뚝 끊겨", "흐름 이어지게", "접속사 정리해 줘" | 흐름 검토만 |
| "AI 티 빼고 보고서에 맞는 공식 용어로 정리해 줘" | 윤문 → 용어 → 흐름 |
| (용어 표를 받은 뒤) "권장만" / "권장+소제목" / "전부" / "1, 3, 7번" | 고른 번호만 적용 |
| (흐름 표를 받은 뒤) "권장만" / "전부" / "F1, F3" / "흐름은 건너뛰기" | 고른 F 번호만 적용 |

같은 "권장만"이라도 **선택을 기다리는 가장 최근 표**(용어 표 / 흐름 표)에 대한 답으로 처리합니다.

윤문 쪽 옵션(`장르: 리포트`, `정밀 모드`, `가볍게` 등)은 원본과 같습니다.

## 테스트

```bash
# 불변 검사 스크립트 단위 테스트
python3 -m unittest discover tests        # 40 passed
```

**행동 테스트** — 스킬 문구는 곧 동작이므로, SKILL.md나 `formal-terms.md`·`flow-review.md`를 고치면 가상 입력으로 다시 확인합니다.

| 확인 항목 | 기준 |
|----------|------|
| 첫 응답에 적용본이 없는가 | "바로 완성본"을 요청해도 표만 낸다 |
| 분류 정답 | [`expected.md`](tests/fixtures/report_excerpt/expected.md)의 A 5 · B 3 · C 2 · D 1 · E 5 (시나리오 프롬프트는 같은 파일, 실제 실행 산출물은 [`runs/`](tests/fixtures/report_excerpt/runs/)) |
| 적용 범위 | 고른 번호만 바뀐다(단어 단위 diff로 확인) |
| 불변 검사 | `check_term_apply.py` exit 0, 바뀐 구간이 고른 번호와 일치 |
| 흐름 후보 | [`flow_excerpt/expected.md`](tests/fixtures/flow_excerpt/expected.md)의 다섯 곳(단문·대조·인과 주의·순서·접속사 과다)과 알림, 실행 산출물은 [`runs/`](tests/fixtures/flow_excerpt/runs/) |

개발 중에는 해당 단계가 없는 상태로 돌린 기준선과 비교했습니다. 용어 검토 기준선에서는 "완성본으로" 요청에 선택 없이 바로 적용하거나 "분포의 꼬리"를 학술 용어로 오분류해 후보에서 숨기는 실패가 나왔습니다. 흐름 검토 기준선에서는 두 번 모두 표 없이 바로 고쳤고, 대조 관계를 표시 없이 넣거나 순서 제안을 아예 하지 않았습니다. 단계를 넣은 뒤에는 모든 시나리오가 통과했습니다.
